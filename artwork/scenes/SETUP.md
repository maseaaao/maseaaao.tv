# Оформление OBS

Геометрия — layout.json, готовые WEBP — корневой dist/artwork/scenes. Размеры: 2560×1440 и 1080×1920. Используются светлая палитра, Unbounded 400 и системный Arial; пустой горизонтальный фон фирменный синий.

Сборка из корня: `bun run render:scenes`. В OBS выбирать WEBP непосредственно из dist/artwork/scenes. Источники камеры, чата, музыки, донатеров и оповещений остаются отдельными. Для статусных сцен после экспорта отдельно выставить их трансформации по картам `horizontal-status` и `vertical-status`; экспорт сам OBS не изменяет. Camera-исходники используют карты `horizontal-camera` и `vertical-camera`; в OBS установлены описанные ниже значения.

В статусных сценах донатеры, чат и соцполоса расположены стык в стык и имеют одинаковую ширину; ниже остаётся музыка, отдельно — alerts и QR. Фон чата непрозрачный с прямыми углами, донатеры и соцполоса рисуются отдельными виджетами. У донатеров скруглены ТОЛЬКО верхние углы; соцполоса во всех сценах одна и та же — без скруглений (один источник виджета, переиспользуемый в каждом входе). Не запекайте данные виджетов в фон.

Сцены камеры сохраняют прозрачные зоны для камеры и динамических виджетов, находящихся под HUD. В вертикальной камерной сцене светлая подложка начинается под соцполосой и проходит под чатом, музыкой и alerts: эти виджеты расположены выше HUD, поэтому их содержимое не перекрывается. Gameplay-фон остаётся прозрачным для игры. Для всех карт `donors` — полный viewport общего источника 1000×134 с одинаковым масштабом по обеим осям; внутренняя панель занимает нижние 114 px, а верхние 20 px прозрачны. Нижний край viewport и панели в статусных, камерных и gameplay-картах стыкуется с камерой или чатом. Для горизонтальной и вертикальной камеры масштабы — 1,28 и 1,08 соответственно; размеры источника и настройки провайдера менять не требуется. У chatFit alignment=5 задаёт якорь, boundsAlignment=9 — выравнивание содержимого; это разные параметры. Музыкальный виджет и донатеры не встраиваются в фон.

### Отдельные browser inputs соцполосы

В `socialSources` указаны **нативные viewport** источников, не размеры после растяжения. Для каждой строки нужен отдельный browser input OBS; экземпляры одной строки можно использовать в нескольких сценах. Текущий общий input 1080×64 с обычным адресом не переопределять: другие сцены могут от него зависеть. Все новые входы открывают один и тот же локальный файл `dist/obs-widgets/social-strip/index.html`; viewport больше 1080 px по ширине в OBS не отрисовывается — полоса в горизонтальной камере берётся из входа 1080×88 и масштабируется равномерно (`horizontalCameraStrip`) под ширину 1280.

| Применение                         | Ширина × высота input | Адрес   |
| ---------------------------------- | --------------------- | ------- |
| Горизонтальные статусные сцены     | 640×88                | обычный |
| Вертикальные статусные сцены       | 720×88                | обычный |
| Шесть горизонтальных gameplay-сцен | 480×88                | обычный |
| Вертикальные камера и gameplay ANY | 1080×88               | обычный |
| Горизонтальная камера (масштаб)    | 1080×88 → 1280×104.3  | обычный |

Все inputs открывают одну страницу виджета с локальным файлом `file:///.../social-strip/index.html` (режим локального файла). Размещать в координатах карты; для горизонтальной камеры — равномерное масштабирование, описанное в `horizontalCameraStrip`. Перед установкой проверить зависимости существующих источников.

`gameplay` в карте — установленная конфигурация OBS с привязкой к шести горизонтальным сценам и вертикальной ANY; координаты `[x, y, width, height]` относятся к холсту. `donors` — полный viewport 1000×134 с равномерным масштабом, `donorVisible` — панель после прозрачных верхних 20 px. Для горизонтальных сцен полоса 480×88 — отдельный browser input; вертикальная 1080×88 — свой вход, чтобы не менять общий 1080×64. Старой полосы в 📁ИГРА больше нет: она скрыта. Музыка остаётся отдельным event-managed виджетом и при отсутствии события прозрачна. Для ANY логотип и alerts смещены вместе с камерой; музыка остаётся на месте. Игровой захват сохраняет crop, масштаб и системный звук; позиция сдвинута под колонку, чтобы камера и полоса не перекрывали игру.

Перед установкой: свежий read-only аудит, резервная копия, проверка общих источников и отсутствия эфира/записи, затем установка и readback геометрии и порядка слоёв. Установленную конфигурацию этого прохода читать из приватного журнала и бэкапа; координаты дробные, OBS может квантовать bounds. Верхние скругления донатеров применяются через provider CSS `dist/obs-widgets/donors/donationalerts-stream-stats.css` — его нужно вставить в Stream Stats донат-сервиса вручную.

После обновления проверить отображение в работающем OBS. Сборка экспортов не изменяет коллекции сцен и не запускает эфир.

HTML собираются Vite/singlefile в `dist/artwork/html/scenes`. Для локального
просмотра: `bun run build:artwork`. Редактируемый CSS — obs-scene.css;
изображения OBS находятся в `dist/artwork/scenes/`.
