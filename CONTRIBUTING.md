# Участие в проекте

maseaaao.tv развивается как один проект с единым релизом.

1. Перед крупной функцией или изменением поведения сначала создайте Issue.
2. Начните с [README](README.md), README затронутого продукта и [правил репозитория](AGENTS.md). Делайте изменения сфокусированными.
3. Работайте в Linux/WSL2 с версиями Bun и Node из `.bun-version` и `.node-version`. Устанавливайте зависимости через `bun install --frozen-lockfile`.
4. Меняйте исходники перед пересборкой. Если изменение влияет на поставляемые файлы, пересоберите соответствующий продукт и включите обновлённые отслеживаемые результаты в pull request.
5. Выполните `bun run check`, нужные сборки и тесты затронутых продуктов, затем `git diff --check`. Полная проверка продуктов — `bun run test`.
6. Не запускайте установку, импорт, Actions, эфир, музыку или отправку сообщений ради проверки. Используйте подставные обработчики; не изменяйте живые настройки и базы.
7. Не добавляйте токены, базы, экспорт с приватными данными, скриншоты с личной информацией или конфигурацию рабочих приложений.
8. В pull request опишите видимый пользователю результат и фактически выполненные проверки. Пользовательские изменения записывайте в корневой [CHANGELOG.md](CHANGELOG.md); выпуск описан в [инструкции релизов](docs/windows-releases.md).

Сохраняйте API, Action ID, имена переменных и параметры подключения. В переводах не изменяйте названия продуктов, `STREAM INFO` и токен `%subtitle%`.
