# Готовые релизы для Windows

Разработка и сборки выполняются в Linux/WSL2. Готовый комплект устанавливается
в Windows вручную из GitHub Releases репозитория `maseaaao/maseaaao.tv`.
OBS, Streamer.bot и Companion устанавливаются отдельно; приложения, рабочие базы,
настройки, токены и резервные копии не входят в релиз.

## Формат релиза

Один тег `vX.Y.Z`, один архив `maseaaao-X.Y.Z.zip` с папками продуктов,
`INSTALL.md` (эта инструкция) и лицензиями. Рядом публикуется `SHA256SUMS`.
Автоматического обновлятора и манифеста установки нет. Внутренние версии
модулей Companion независимы от версии комплекта и нужны для TGZ-импорта.

## Установка и обновление

1. Скачать ZIP и `SHA256SUMS` одного опубликованного выпуска. Для приватного
   репозитория войти в GitHub через браузер; не сохранять токен в папке комплекта.
2. Сверить SHA256 ZIP со строкой в `SHA256SUMS` этого же выпуска, например:

   ```powershell
   Get-FileHash -Algorithm SHA256 '.\maseaaao-1.0.0.zip'
   ```

3. Распаковать ZIP в новый пустой каталог Windows. Не распаковывать поверх
   прежнего комплекта: удалённые файлы не должны оставаться рядом с новыми.
   WSL-пути не использовать для постоянных ресурсов Windows-приложений.
4. Сохранить прежний комплект, изменённые вручную ресурсы, штатные экспорты
   затронутых приложений и предыдущие TGZ. Пользовательские данные хранить отдельно.
5. В согласованное окно без эфира подключить новые ресурсы через интерфейсы
   приложений. Сохранять ID, размеры, положение, URL-параметры и настройки.
   Если нужен прежний постоянный путь, штатно закрыть использующие файлы
   приложения, переименовать старую папку для отката и поставить новую на её место.
   Это ручная замена, не бесшовное обновление во время эфира.
6. Проверить пути и отображение ресурсов, загрузку INFO и версии модулей чтением
   состояния. Перезагрузить соответствующие доки и браузерные источники OBS.
   Распаковка не устанавливает C#, TGZ или provider CSS и не меняет конфигурацию.

## Подключение продуктов

Пути указаны относительно распакованного комплекта:

| Продукт              | Что подключить                                                                                      |
| -------------------- | --------------------------------------------------------------------------------------------------- |
| Stream Info          | `stream-info/change-info-streamer-bot.ru.html` — док OBS; `stream-info/` — файлы HTTP-маппинга      |
| Tuna                 | `tuna-widget/obs-tuna-widget.html`, сохранив прежние URL-параметры                                  |
| OBS widgets          | `obs-widgets/social-strip/`; CSS и Custom JS провайдеров устанавливать отдельно через их интерфейсы |
| Artwork              | `artwork/scenes/`, `artwork/logo/`, остальные изображения в `artwork/`                              |
| SystemMicrophone     | TGZ из `system-microphone/`                                                                         |
| VoiceStream          | TGZ из `voice-stream/`                                                                              |
| Windows integrations | `windows-integrations/README.md`, запускатель, `diagnostics/`, C#-шаблоны и звуки в `actions/`      |
| Website              | `website/` — статические файлы; установка комплекта не публикует сайт                               |

Изменённый C# импортировать отдельно в существующие Actions Streamer.bot,
сохраняя ID, и скомпилировать Execute Code внутри приложения. Для Stream Info
используется `stream-info/streamerbot-import.txt`; HTML сам по себе API не обновляет.
Пути к MP3 в C# настроить на выбранный каталог: звуки находятся в
`windows-integrations/actions/chat-sound/notif.mp3` и
`windows-integrations/actions/obs-health/health-warning.mp3`.
Секреты DonationAlerts остаются в приватных переменных Streamer.bot.

Перед импортом TGZ Companion сохранить штатный экспорт и проверить настройки:
у SystemMicrophone явно задан `dataFlow=capture` или `render`, endpoint ID сохранён;
у VoiceStream заданы два различных UUID существующих включённых Actions запуска
и остановки. Если проверка не пройдена, остановить обновление. Импортировать TGZ
через менеджер модулей и выбрать версии в **существующих соединениях**. Сохранить
ID соединений, кнопки, назначения, feedback и секреты; не пересоздавать соединения.
Затем сверить фактические `moduleVersionId`, настройки, состояние и журнал.
Не запускать `main.js` и EXE помощников напрямую для проверки.

Для запускателя и диагностики нужен Windows Bun; сам Companion использует
свой комплектный Node. Перед запуском задать фактический путь Streamer.bot,
не полагаясь на соседние папки:

```text
bun windows-integrations/start-companion.mjs --streamerbot-root <полный-путь>
bun windows-integrations/diagnostics/check-stream-stack-cli.mjs --streamerbot-root <полный-путь>
```

Проверке процесса нужен штатный Windows Script Host/WMI и соседний
`windows-integrations/companion-processes.wsf`; при ошибке проверки запуск
блокируется. Диагностика не выполняет Actions, но сохраняет отчёт в
`custom/maintenance/stream-stack-latest.json` внутри установки Streamer.bot.
Эфир, сцены, mute, музыку и сообщения не менять ради проверки.
Не редактировать живые базы, JSON или Junction при работающем владельце.

## Откат

Сохранить новый комплект отдельно и вернуть прежнюю папку либо пути ресурсов
через интерфейсы приложений. При блокировке файлов штатно закрыть владельца,
не завершать процессы принудительно. Прежний комплект удалять только после
проверки всех потребителей, включая ярлыки и коллекции OBS.

Возврат файлов не откатывает импортированный C# и выбранную версию Companion.
Их вернуть отдельно в прежних Actions и соединениях. При необходимости
восстановить совместимый штатный экспорт средствами приложения; не копировать
базу поверх работающего владельца.

## Выпуск для разработчика

В Linux/WSL2 нужны Bun из `.bun-version`, .NET SDK 8, системный `tar`
и браузер для проверок оформления. Использовать зависимости из `bun.lock`.
1. Добавить описание в корневой `CHANGELOG.md` под `## X.Y.Z`.
2. Выполнить `bun run check` и `bun run test`.
3. Собрать, проверить и упаковать комплект (пример версии):

   ```bash
   bun run test:releases
   bun tooling/bundle-release.mjs --build v1.0.0
   bun tooling/bundle-release.mjs v1.0.0
   ```

   `--build` собирает и тестирует продукты; отдельная следующая команда создаёт
   `build/release/v1.0.0/maseaaao-1.0.0.zip`, `SHA256SUMS` и `notes.md`.
   Проверить архив, инструкцию и лицензии перед выпуском.
4. Только по отдельному поручению создать и отправить тег на проверенном коммите.
   Workflow `Release` собирает комплект и создаёт черновик GitHub Release;
   ручной запуск workflow также требует существующий тег.
5. Проверить черновик и только по отдельному поручению опубликовать его.

Для исправления опубликованного комплекта выпустить новую версию, не подменять
старый выпуск. Релиз не публикует сайт в Cloudflare и не устанавливает ресурсы
в работающие OBS, Streamer.bot или Companion.
