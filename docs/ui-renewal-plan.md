## Архитектурное предложение

### Исходники и результаты

Статическая поставка не означает отсутствие JavaScript. После сборки Vue SFC превращаются в JS/CSS; интерактивный результат содержит необходимую часть Vue runtime как обычный встроенный JS. Компилятор шаблонов в браузере не нужен. Для неподвижной разметки Vue выполняется при сборке, и клиентский runtime не включается.

| Потребитель                                  | Предлагаемый результат                                            | Условия                                                                                                       |
| -------------------------------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| Stream Info                                  | Один интерактивный HTML                                           | CSS/JS/шрифты встроены; прежний внешний Streamer.bot API                                                      |
| Tuna, соцполоса, статистика OBS              | Отдельный автономный HTML на продукт                              | Сохранить источники данных и настройки; JS только для нужного поведения                                       |
| Сайт                                         | Статически сформированные страницы с необходимой интерактивностью | Сохранить маршруты, SEO и публичные ресурсы; CSS/JS встраивать в страницы, если ограничения CSP это позволяют |
| Баннеры, сцены, панели, обои и brand artwork | HTML для подготовки и конечные изображения                        | Фиксированные размеры, safe zones, прозрачность, локальные ресурсы                                            |
| Streamlabs, DonationAlerts                   | Поддерживаемые провайдером CSS/HTML/JS                            | Общие токены и необходимые стили; сохранить placeholders и события провайдера                                 |

Независимость означает отдельный готовый результат для каждого продукта, а не один гигантский HTML для всего репозитория. Сайт сохраняет несколько маршрутов; обязательные публичные ресурсы и ссылки на загрузки не удаляются ради формального single-file. Для локального инструмента обязательные ресурсы интерфейса должны быть внутри HTML. Внешние API, трансляция, чат и динамическая обложка — функциональные зависимости, а не скрытые зависимости сборки.

### Пакеты

| Область               | Ответственность                                                                            |
| --------------------- | ------------------------------------------------------------------------------------------ |
| packages/design       | Семантические токены, шрифты, лицензии, правила композиции                                 |
| packages/ui           | Общие Vue-компоненты с типизированными props/events/slots и документированными состояниями |
| apps/*                | Экраны, бизнес-логика, адаптеры внешних API и продуктовые компоненты                       |
| artwork               | Исходные композиции и утверждённые ресурсы; существующие конечные пути экспортов           |
| packages/build-config | Общие настройки сборки; не runtime-зависимость                                             |
| Storybook workspace   | Каталог компонентов, правил, экранов и artwork на подставных данных                        |

Общие фирменные композиции выделять в отдельный пакет только при подтверждённом использовании несколькими потребителями. Не создавать универсальный компонент с десятками переключателей для сайта, дока и баннера. Одноразовый продуктовый компонент может оставаться локальным и иметь story в общем каталоге.

### Инструменты и альтернативы

Рекомендуемая база: Vue 3 SFC + TypeScript, Vite с официальным Vue plugin, существующий singlefile для автономных приложений, Storybook Vue/Vite, Vitest, Playwright, Sharp и PostCSS. Добавления обоснованы компонентной моделью, проверкой SFC и каталогом состояний. Совместимость версий проверяется для технического образца на этапе 2 и закрепляется для всей среды на этапе 4; без безусловного latest.

- Для статического рендера сравнить ровно два кандидата: Astro с официальной Vue-интеграцией и Vite с официальным Vue server-renderer и минимальной сборочной обвязкой. Первый предпочтителен как готовое решение, если проходит требования поставки; второй допустим, если сокращает общую сложность без создания собственного генератора сайтов.
- Оба кандидата проверить на одинаковых трёх примерах: статическая страница, страница с интерактивным Vue-блоком и фиксированный artwork. Оценить сбор CSS/ресурсов, маршруты, автономность, отсутствие клиентского Vue в статическом результате, повторяемость, размер JS и объём собственного кода. Astro не переносить автоматически на автономные доки.
- После этих примеров выбрать один основной путь статической генерации для сайта и artwork и удалить экспериментальную альтернативу. Не поддерживать две реализации одного компонента или два постоянных статических генератора. Если оба кандидата не проходят обязательные требования, зафиксировать конкретные причины и пересмотреть решение до массового переноса. Не писать шаблонизатор или регулярные замены HTML вместо сборщика.
- Web Components позволяют использовать элементы в разных frontend-стеках, но не обеспечивают single-file и не устраняют JS. Vue custom elements сохраняют Vue runtime. Shadow DOM при его использовании меняет стилизацию, слоты и взаимодействие с формами. Для внутреннего Vue-монорепозитория это пока лишняя граница; оставить для реального внешнего потребителя.
- Нативные custom elements без Vue уменьшают зависимость от framework, но требуют другой модели реализации и проверок поведения. Не поддерживать две реализации одних интерактивных компонентов ради формального отсутствия Vue.
- Microfrontends и runtime federation не нужны: независимость выпусков обеспечивается отдельными сборочными entrypoints и workspace-пакетами. Nx/Turborepo вводить только при измеренной потребности, не ради самого монорепозитория.

## Решения, которые уточняются по результатам исследования

- Точный инструмент предварительного рендера: решено пользователем на этапе 4 — Vite + официальный Vue SSR server-renderer, без формального сравнения с Astro (см. этап 4, пункт про сравнение кандидатов). Astro не отброшен по измеренным недостаткам; если в будущем понадобится независимая оценка — переоткрыть отдельным пунктом.
- Версии зависимостей и возможное обновление Vite: после проверки совместимости, без произвольной миграции на major.
- Границы общих фирменных композиций и конкретный перечень компонентов: после полной инвентаризации.
- Поддерживаемые версии OBS/браузеров: зафиксировать на этапе 2; численные бюджеты: по измерениям окончательной цепочки на этапе 4.
- Визуальные эталоны требуют предметной оценки; зелёные линтеры и screenshots не доказывают качество самого дизайна.
