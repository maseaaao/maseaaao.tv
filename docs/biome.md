# Biome: политика исходников

Единственный formatter, organizer импортов и линтер — **Biome 2.6.2**, закреплённый без диапазона в корневом package.json и pnpm-lock.yaml. Конфигурация — корневой `biome.json`, дополнительные правила — `tooling/biome/*.grit`. ESLint, Stylelint, Prettier и их прямые зависимости удалены.

## Повседневные команды

| Команда                                    | Что делает                                                                                                          |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------- |
| `pnpm run check:biome`                     | Проверяет формат, импорты и lint; не пишет файлы, предупреждения блокируют приёмку.                                 |
| `pnpm run check:fix`                       | Применяет форматирование, организацию импортов и только безопасные исправления.                                     |
| `pnpm run format`, `pnpm run format:check` | Отдельно форматирование и его проверка.                                                                             |
| `pnpm run lint`, `pnpm run lint:fix`       | Отдельно lint и безопасные исправления lint.                                                                        |
| `pnpm run test:source-policy`              | Проверяет политику на корректных и намеренно ошибочных исходниках через настоящий Biome.                            |
| `pnpm run check:source`                    | Biome, тесты политики, проверки типов всех workspaces и предметные контракты исходников. Работает без готовых dist. |
| `pnpm run check`                           | Также проверяет наличие и согласованность результатов сборок.                                                       |

CI уже вызывает `check:source`: отдельный параллельный набор линтеров не нужен. Изменения конфигурации и плагинов инвалидируют кеш Turbo. VS Code использует `biomejs.biome` и `source.fixAll.biome`; Vue language service остаётся ответственным за типы и подсказки шаблонов.

## Выбранные правила

- Основа — рекомендованные правила стабильных групп, с дополнительным доменом Vue. Не включать `all`: он содержит альтернативные стили и требования других фреймворков, а не только проверки ошибок.
- Неиспользуемые импорты, переменные и параметры, необъявленные имена, явный `any`, non-null assertions, `@ts-ignore`, debugger и focused tests — ошибки.
- `noFloatingPromises` и `noMisusedPromises` включены явно из nursery. Версия инструмента закреплена, чтобы обновление экспериментального анализа было проверяемым изменением. `void` допустим только для сознательно обрабатываемых фоновых задач; это не обработчик отказа Promise.
- Импорты внутренних `src` чужих продуктов запрещены; пользоваться workspace exports.
- В Vue, UI и Storybook сохраняется запрет приведений типов: GritQL сопоставляет `TsAsExpression` и `TsTypeAssertionExpression`, включая скрипты SFC. Проверять границы значений и сужать типы защитными условиями. `satisfies` допустим.
- CSS проверяется также внутри HTML и Vue. В значениях CSS деклараций Vue запрещены hex/rgb/hsl, включая градиенты, тени и функции: использовать семантические токены. `color-mix` с токенами разрешён.
- Нативные проверки доступности включены. Проверки doctype, языка и заголовка документа, а также обнаруживаемой DOM-вложенности интерактивных элементов остаются предметным контрактом `tooling/source-markup.mjs`: у Biome 2.6 нет полного аналога прежних document-level HTML-правил. Провайдерский Streamlabs HTML — фрагмент; doctype, lang и title ему не нужны.
- Два пробела, LF, 100 колонок, одинарные JS/TS-кавычки, обязательные semicolons и trailing commas. HTML whitespace sensitivity — `strict`: пробелы могут менять вывод inline-элементов. Markdown не переформатирует вложенные примеры команд и кода.

## Исключения и ограничения

Сгенерированные `dist`, `.build-cache`, `build`, `rendered`, .NET `bin`/`obj`, скомпилированные Companion main.js и streamerbot-import.txt исключены. Lockfile пишет только pnpm. Двоичные и неподдерживаемые форматы не обрабатываются. SVG-ресурсы исключены: это сохраняет исходные байты artwork и публичной статики. Содержимое outputs проверяют сборки и тесты, а не повторное форматирование.

Повторные CSS-селекторы, порядок специфичности и `!important` допускаются: исходники используют каскад состояний, адаптацию провайдеров и принудительное отключение анимации для reduced motion. Дубликаты деклараций, неизвестные свойства, функции и прочие рекомендованные проверки остаются включены. Не вводится сортировка CSS-деклараций: перестановка shorthand/longhand может менять каскад.

`useTemplate` и `useVueNextTickPromise` отключены как предпочтения записи, не проверяющие корректность. `noUndeclaredEnvVars` отключён: локальные скрипты читают самостоятельные параметры окружения вне Turbo-контракта. Браузерные тесты сохраняют `innerText`: они проверяют видимый текст, включая отличие от скрытых узлов. В смешанных Playwright-файлах разрешены и браузерные, и Node globals.

Точечные `biome-ignore` рядом с кодом объясняют неформовые ARIA-группы, намеренно глобальный artwork style и ложное срабатывание `noInvalidGridAreas` на валидных одноколоночных строках. Для SettingsDialog (pointer-backdrop с отдельным обработчиком клавиатуры) и AppButton (доступное содержимое через Vue slots/ariaLabel) сделаны overrides ровно одного правила на один файл: комментарий перед корневым узлом SFC может превратить корень в Fragment и нарушить Vue Transition. Не добавлять отключения всего файла ради отдельного замечания.

Полная обработка Vue/HTML в Biome остаётся экспериментальной. Результат проверяется `vue-tsc`, сборками, браузерными тестами и тестами политики, а версия инструмента меняется вместе с этими проверками. Biome не является побуквенной заменой всех type-aware правил typescript-eslint и всех проверок значений Stylelint; например, прежний `unbound-method` не имеет здесь включённого эквивалента. Не считать один зелёный lint доказательством корректности типов, шаблонов или runtime. Перед добавлением нового строгого правила проверить реальный код и добавить отрицательный тест, если правило защищает проектный контракт.
