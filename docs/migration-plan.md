# План завершения миграции

Рабочие исходники — `maseaaao.tv`. Этот план относится к будущему обновлению установленных приложений; перенос исходников сам по себе его не выполняет.

1. **Подготовить откат.** Сохранить штатные экспорты Streamer.bot и Companion, копию коллекции/профиля OBS и текущих браузерных ресурсов. Проверить фактические пути, Junction Companion и активную БД; не заменять рабочие данные историческими копиями. Не править файлы конфигурации при работающем владельце.
2. **Проверить выбранный коммит.** Node.js 22.20+ в ветке 22, .NET 8; выполнить `npm ci`, `npm run browser:install`, `npm run check`, `npm run check:stream-info`, `npm test`, `npm run build:stream-info`, `npm run build:tuna`. При обновлении модулей отдельно собрать и упаковать их по README.
3. **Обновить браузерные ресурсы по одному продукту.** Из корня выполнить `npm run sync:local -- --product <группа>`, проверить план, затем повторить с `--apply`. Группы: `artwork`, `widgets`, `tuna`, `stream-info`, `brand-color-lab`; для другой установки указать `--obs-root`. Старые пути поддерживаются, оформление и шрифты восстанавливаются вместе. Перезагрузить доки/источники OBS, проверить размеры, светлую тему и шрифты; у Tuna — настоящий трек.
4. **Обновить интеграции отдельно.** HTML не обновляет Execute Code. При изменении C# импортировать Stream Info в существующий Action с сохранением ID и проверить компиляцию. Для нового DonationAlerts заранее задать приватную глобальную `daClientSecret`, не включать её в Git/HTML/экспорты для публикации. Проверить путь `control.ps1` в Actions Яндекс Музыки. Companion обновлять через менеджер модулей, сохраняя соединения, кнопки и настройки; сверить загруженную версию. Процедуры — [локальная установка](local-installation.md).
5. **Проверить систему и откат.** Выполнить диагностику чтения с `STREAMERBOT_ROOT`, проверить ссылки кнопок на Actions, доступность HTTP/WS и локальных файлов. В OBS проверить действующую коллекцию и док INFO. Эфир, метаданные, сообщения, переключение сцен и звук проверять только в согласованном тесте. При проблеме восстановить заменённые ресурсы из `Streamer.bot/backup/monorepo-sync-*`; конфигурации и модули — штатным восстановлением совместимых экспортов. Записать коммит, версии и результат ручной проверки.
6. **Выпустить Stream Info из нового репозитория.** По [порядку выпуска](releasing.md) создать тег `stream-info-vX.Y.Z`, дождаться черновика, проверить скачанные HTML/ZIP и импорт в тестовой установке, затем опубликовать. Обновить ссылки на сайте и в документации на конкретный выпуск; общий `releases/latest` не разделяет продукты. Прежние релизы не переносить повторной загрузкой и не удалять.
7. **Закрыть переход старого репозитория.** После проверенного нового выпуска добавить в начало обоих README старого `change-info-streamer-bot` уведомление со ссылками на `maseaaao.tv/tree/main/apps/stream-info`, новые Issues и конкретный релиз; обновить About. Разобрать открытые Issues/PR, включая PR №3: проверить, что полезные изменения уже перенесены, затем закрыть или перенести обсуждение с перекрёстной ссылкой. Отключить старые workflow, после чего архивировать репозиторий. Сохранить его имя, историю, теги и старые артефакты; не удалять и не переименовывать.

До выполнения пунктов 6–7 старый репозиторий остаётся доступен без архивирования. Новую разработку вести только в монорепозитории. [Архив GitHub доступен для чтения и может быть разархивирован](https://docs.github.com/en/repositories/archiving-a-github-repository/archiving-repositories).
