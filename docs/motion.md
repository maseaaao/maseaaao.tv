# Движение maseaaao

Движение помогает почувствовать действие и понять смену состояния. В покое интерфейс неподвижен. Ориентиры — сдержанность Apple HIG и последовательность Fluent; конкретные числа ниже выбраны для этого проекта, а не выданы за точные параметры iOS или Windows.

## Характер

Поверхности сохраняют положение. На hover меняется цвет, на focus сразу появляется контрастная рамка. При нажатии кнопка опускается на 1 px, не сжимая надпись. Отпускание мягче нажатия. Маленькая панель появляется рядом с причиной своего появления; крупные области не летают через экран. Нет отскоков, параллакса, магнитного курсора, пульсации LIVE и анимации букв.

Важнее непрерывность, чем эффект: повторное нажатие разворачивает CSS transition из текущего положения. Поиск анимирует появление контейнера один раз, а не каждую порцию результатов. Нажатие не ждёт окончания движения. Для клавиатуры вступление главной сразу прекращается при фокусе внутри поверхности.

## Общая шкала

Источник — `packages/design/motion.css`, включённый в `@maseaaao/design/tokens.css`. Значения применяются по смыслу, не задают одинаковую скорость всем продуктам.

| Токен            | Значение | Назначение                                         |
| ---------------- | -------- | -------------------------------------------------- |
| `--motion-press` | 80 ms    | нажатие на 1 px                                    |
| `--motion-state` | 160 ms   | цвет, отпускание, появление результатов поиска     |
| `--motion-exit`  | 160 ms   | закрытие окна                                      |
| `--motion-enter` | 280 ms   | появление окна                                     |
| `--motion-intro` | 360 ms   | вступление главной                                 |
| `--motion-step`  | 35 ms    | короткий сдвиг начала между тремя группами главной |

`--motion-ease-out: cubic-bezier(.2,.8,.2,1)` быстро отвечает и плавно останавливается. `--motion-ease-in: cubic-bezier(.4,0,1,1)` уводит закрываемое окно. `--motion-ease-state: cubic-bezier(.2,0,.2,1)` связывает состояния цвета. Кривые монотонные, без перелёта. Это собственные параметры, не симуляция физической пружины с сохранением скорости.

## Сценарии

| Где                   | Движение                                                                               | Ограничение                                                                                                     |
| --------------------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Главная               | имя, ссылки, контакты: 6 px снизу, opacity .65 → 1; задержки 0/35/70 ms                | весь эпизод ≤430 ms; ссылки доступны сразу; отдельные кнопки не выстраиваются в очередь                         |
| Кнопки и ссылки       | цвет за 160 ms; нажатие 1 px за 80 ms, возврат за 160 ms                               | без движения на hover/focus; disabled/loading не реагируют на нажатие                                           |
| Настройки Stream Info | фон плавно затемняется, окно проходит 8 px и scale .985 → 1 за 280 ms; выход за 160 ms | анимируется локальное окно; размер/переносы текста не меняются                                                  |
| Закрытие настроек     | фон остаётся inert до конца выхода; уходящее окно inert и скрыто от accessibility tree | после удаления окна фокус возвращается на исходную кнопку; новое открытие не получает запоздалый возврат фокуса |
| Поиск категории       | контейнер появляется с −4 px и opacity .65 → 1 за 160 ms                               | результаты не задерживаются; обновление списка не запускает вступление заново; закрытие немедленное             |

На главной остаётся статический HTML без клиентского JS/Vue. Анимация не прячет информацию до загрузки скрипта. Движутся только transform/opacity; цвет меняется локально у контролов. Нет анимации layout, blur, постоянного `will-change` и JS-цикла кадров. Это ограничения реализации, а не доказательство стабильных 60 FPS на любом устройстве.

## OBS

Вещательный overlay имеет другую задачу: движение не должно спорить с игрой. Сохранены уже согласованные в коммитах `f9f059e` и `eed2684` сценарии:

- донатеры: перекат текста за 520 ms внутри неподвижного фона, без гашения;
- соцполоса: волна 1.56 s раз в 30 s, неподвижные ник и поверхность;
- Tuna: собственное прерываемое появление/исчезновение, смена обложки, маска и постоянная скорость длинного текста; функциональные тайминги остаются в приложении.

Общие интерфейсные токены не подменяют эти тайминги. Явное включение движения в OBS (`motion=1`, CSS override) остаётся выбором владельца источника; сайт и док не обходят системную настройку. Проверка браузерной сборки не устанавливает ресурсы в рабочий OBS и не подтверждает поведение его CEF.

## Доступность и проверка

`prefers-reduced-motion: reduce` обнуляет токены и отключает необязательные анимации/переходы; нажатия неподвижны, окно не масштабируется, действия сохраняют свою семантику. Изменение настройки при открытой странице также действует. Текст и семантические состояния сохраняются.

Проверять собранную доставку: 320/390/540 и desktop; клавиатуру; close во время enter; повторное открытие; disabled/loading; смену reduced-motion; отсутствие движения в покое и переполнения. Для сайта также отключить JS. Для дока использовать только `?demo` и подставной транспорт, без живых Action.

```sh
npm run build:all
npm run check
node --test tests/motion.test.mjs tests/landing-corrections.test.mjs tests/stream-info-delivery.test.mjs tests/stream-info-transport.test.mjs tests/tuna-widget.test.mjs tests/donors-slide.test.mjs tests/obs-widgets.test.mjs
```

Первичные ориентиры: [Apple HIG: Motion](https://developer.apple.com/design/human-interface-guidelines/motion), [Fluent 2: Motion](https://fluent2.microsoft.design/motion), [Windows: Timing and easing](https://learn.microsoft.com/en-us/windows/apps/design/motion/timing-and-easing). Приёмка ощущений и плавности требует также просмотра на реальных устройствах; автоматические проверки ловят нарушение поведения, но не утверждают художественное качество.
