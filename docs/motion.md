# Движение и анимации

Единая система движения для браузерных продуктов maseaaao.tv. Источник значений —
`packages/design/tokens.css`; общие примитивы — `packages/design/motion.css`.
Правила дизайна — [design.md](design.md). Живые примеры всех таймингов и кривых —
[maseaaao.tv/ui/#motion](https://maseaaao.tv/ui/#motion).

## Зачем система

Движение объясняет изменение: нажатие подтверждается сразу, новая поверхность
появляется оттуда, откуда её ждут, а исчезающая — освобождает место. Оно не
заменяет текст статуса, не задерживает действие и не становится единственным
носителем смысла.

Основа — две школы, сведённые в одну шкалу:

- **Windows 11 / Fluent.** Длительности 83, 167, 250 и 333 мс; вход
  `cubic-bezier(0, 0, 0, 1)`; выход `cubic-bezier(1, 0, 1, 1)`; связанность,
  согласованность и «не изобретать движение там, где есть системное».
  [Motion in Windows](https://learn.microsoft.com/windows/apps/design/signature-experiences/motion),
  [Timing and easing](https://learn.microsoft.com/windows/apps/design/motion/timing-and-easing).
- **iOS / HIG.** Движение по назначению, краткое и точное, отменяемое; пружина
  вместо линейной доводки; при `Reduce Motion` пространственные переходы
  заменяются fade, пружины стягиваются, blur не анимируется.
  [Motion](https://developer.apple.com/design/human-interface-guidelines/motion),
  [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility),
  [SwiftUI spring](https://developer.apple.com/documentation/swiftui/animation/spring(response:dampingfraction:blendduration:))
  (по умолчанию response 0,5 с, dampingFraction 0,825).

Мы берём у Windows сетку времени и вход без перелёта, у iOS — упругую доводку
интерактивных элементов и staged-появление содержимого. Это не буквальная копия
платформ: выход смягчён до `cubic-bezier(0.4, 0, 1, 1)`, потому что на 167 мс
кривая `(1, 0, 1, 1)` читается как задержка, а фокус получает отдельные 120 мс
ради читаемости кольца.

## Принципы

1. **Сначала отклик, потом красота.** Нажатие меняет цель в течение одного кадра;
   анимация не ждёт отпускания.
2. **Одно объяснение на изменение.** Вход — снизу и с fade; выход — вниз/в сторону
   и быстрее входа. Не двигаем то, что не меняет положение.
3. **Прозрачность и blur — рабочие инструменты.** Fade и короткий blur (≤120 мс)
   отделяют слои и смягчают смену содержимого; это не запасной вариант, но и не
   повод размывать весь экран надолго.
4. **Коротко и прерываемо.** 83–333 мс; новый ввод отменяет старый, а не встаёт
   в очередь. Никаких «дождитесь окончания анимации».
5. **Содержимое отдельно от подложки.** Поверхность появляется первой, текст —
   на 20–25 % позже; при закрытии порядок обратный.
6. **Hover не двигает цель.** Меняются цвет, граница, тень, блик и стрелка;
   геометрия — только у нажатия и входа.
7. **Reduce Motion — не «выключить всё», а убрать перемещение.** Конечное
   состояние остаётся, информация не прячется, тайминги провайдеров сохраняются.
8. **Движение не должно быть дорогим.** Постоянно — `transform`, `opacity` и
   короткий `filter`; blur на большой поверхности — только на время смены слоя.

## Токены

| Токен                  | Значение                     | Назначение                                    |
| ---------------------- | ---------------------------- | --------------------------------------------- |
| `--motion-press`       | 83 ms                        | нажатие, активное состояние                   |
| `--motion-focus`       | 120 ms                       | появление/смена фокуса, blur-доводка          |
| `--motion-feedback`    | 167 ms                       | hover, цвет, граница, статус, мелкий fade     |
| `--motion-enter`       | 250 ms                       | появление поверхности, popover, карточки      |
| `--motion-exit`        | 167 ms                       | исчезновение, закрытие                        |
| `--motion-scene`       | 333 ms                       | смена сцены/ветки, вход группы                |
| `--motion-rise`        | 8 px                         | подъём при входе                              |
| `--motion-nudge`       | 4 px                         | малый сдвиг/выход                             |
| `--motion-shift`       | 12 px                        | перекат текста                                |
| `--motion-press-scale` | 0.985                        | сжатие при нажатии                            |
| `--motion-enter-scale` | 0.97                         | масштаб входа поверхности                     |
| `--motion-blur`        | 2 px                         | короткая фокусная доводка                     |
| `--motion-ease-state`  | `cubic-bezier(0.2, 0, 0, 1)` | цвет, прозрачность, состояние                 |
| `--motion-ease-enter`  | `cubic-bezier(0, 0, 0, 1)`   | вход: быстро пришёл, мягко встал              |
| `--motion-ease-exit`   | `cubic-bezier(0.4, 0, 1, 1)` | выход: ускоряется и освобождает место         |
| `--motion-ease-spring` | `linear(...)` / cubic-bezier | упругая доводка: 8 % перелёта, покой к 333 мс |

`--motion-ease-spring` использует `linear()` с 25 отсчётами пружины
`1 - e^(-8t)(cos 10t + 0.8 sin 10t)`, нормированной к 1. Где `linear()` не
поддерживается, остаётся `cubic-bezier(0.2, 1.22, 0.36, 1)` с тем же характером.
Проверено в Chromium 150 (OBS CEF) и Chromium 1.64 Playwright: поддержка есть.

## Reduce Motion

При `prefers-reduced-motion: reduce`:

- входы/выходы и hover-переходы отключаются, элементы сразу в конечном состоянии;
- пространственные сдвиги и масштаб не показываются; fade допустим, но не обязателен;
- `Tuna` получает `anim = 0`, `swap = 0` и завершает уже начатые анимации в
  конечной позе, не сбрасывая таймеры показа;
- чат сохраняет провайдерную задержку `fadeAway` (она управляет удалением, а не декором);
- донатеры продолжают эфирную анимацию: это содержание трансляции, а не интерфейс
  оператора. Это осознанное исключение, закреплённое тестами.

## Производительность и прерывание

- Постоянные переходы — `transform`, `opacity` и короткий `filter: blur` (≤120 мс).
  Blur полезен для смены текстового слоя, popover, уведомления и модалки; не стоит
  размывать полноэкранный фон или держать blur дольше одного короткого перехода.
- Никаких постоянных `requestAnimationFrame`-циклов. Tuna использует WAAPI только
  на время перехода и отменяет предыдущий; остальные продукты — CSS-переходы.
- CSS-переход сам берёт текущее вычисленное значение: быстрый повторный клик
  продолжает с текущей позы, а не с начала.
- Вход не блокирует указатель: элементы кликабельны во время анимации.
- Модалка возвращает фокус сразу, даже если подложка ещё 167 мс исчезает.

## Проверенные гипотезы

Проверки выполнялись в локальном Chromium 150 (Windows) на реальных страницах
dev-запускателя; это не заменяет приёмку в OBS CEF, но фиксирует поведение
анимаций и отсутствие грубых регрессий.

| Гипотеза                                                | Результат                                                                                                                             |
| ------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Пружина `linear()` даёт управляемый перелёт, а не рывок | Перелёт 7,8 % на ~114 мс, возврат к 100 % к ~180 мс; кривая укладывается в 333 мс.                                                    |
| Короткий blur не вызывает просадки на сетке карточек    | 80 карточек с `blur(2px)` и без него: медиана кадра 5,55 мс в обоих случаях, кадров >20 мс — 0. Это лабораторный замер, не FPS в OBS. |
| Hover не двигает layout                                 | `layout-shift` за обход всех плиток и контактных ссылок — 0.                                                                          |
| Модалка закрывается, не блокируя действие               | Фокус возвращается сразу; подложка снимается через 167 мс; при `reduce` — сразу.                                                      |
| `reduce` оставляет конечное состояние                   | Website и Stream Info: `opacity: 1`, `transform: none`, `filter: none` уже через 50 мс; Tuna: `--art-swap: 0ms`.                      |
| `linear()` поддерживается целевым Chromium              | `CSS.supports('animation-timing-function', 'linear(0, 1)')` — true в Chromium 150 (OBS CEF) и Playwright Chromium.                    |
