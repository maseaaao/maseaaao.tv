# Визуальные правила и эталоны

Этап 3. Предложение для согласования, 19.10.2026. Это воспроизводимые макеты, а не готовые продукты; функциональные контракты остаются в [реестре](../ui-renewal-inventory.md). API, эфир и рабочие настройки здесь не используются.

## Основа и композиция

Основной референс — [maxxborer.com](https://maxxborer.com), просмотренный в браузере при подготовке эталонов: синий внешний фон, светлая поверхность с мягким радиусом, крупное имя, выразительная первая ссылка и спокойные вторичные действия. Используем эту логику иерархии для стримера: сначала имя и переход на Twitch, затем поддержка, социальные сети, плеер/чат и контакты. Стрелка обозначает переход по ссылке, а не декоративный движущийся элемент.

[Сайт Hermes](https://hermes-agent.nousresearch.com/) остаётся вторичным ориентиром: ясное разделение задач и спокойная подача содержимого. Детали Hermes Desktop не исследованы и не объявляются источником проверенных паттернов. Интерфейс стрима не получает терминальную/тёмную тему, чужие шрифты или декоративную текстуру.

Отличительный приём — крупная спокойная типографика на единой светлой поверхности внутри синей области. Иерархия строится размером, интервалами и одним главным действием, а не сеткой одинаково акцентных карточек. Док сохраняет синий внешний фон, светлую поверхность и выразительную типографику; рамка и интервалы компактнее сайта. Для artwork синяя область становится рамкой, а светлая поверхность связывает сцену с сайтом.

## Предлагаемые семантические токены

Пока живут только в reference.css. После согласования перенести в packages/design, временные hud aliases удалить только после всех потребителей. Цвета существующей палитры сохраняют узнаваемость; меняются композиция и типографическая иерархия.

| color-surface        | #f4f3ec  | основная светлая поверхность                     |
| color-field          | #fffef8  | поля, медиаповерхности                           |

Текст на цвете всегда проверять парой: основной/вторичный текст минимум 4.5:1, крупный 3:1; границы интерактивных контролов и фокус 3:1. Светлая декоративная граница не служит единственным обозначением интерактивного элемента. Статусы включают текст, не только цвет/точку. Значения contrast проверяются на эталонах, затем на конечных состояниях продуктов.

## Типографика

| Роль                               | Шрифт / вес   | Размер / line-height                                                  |
| ---------------------------------- | ------------- | --------------------------------------------------------------------- |
| Имя на сайте                       | Unbounded 400 | 72 / 1.1 desktop, 28–40 / 1.1 mobile; tracking -.055em                |
| Заголовок раздела сайта            | Unbounded 400 | 22 / 1.4, 19 на узком экране                                          |
| Главная ссылка сайта               | Unbounded 400 | 20 / 1.35, 17 mobile                                                  |
| Заголовок дока                     | Unbounded 400 | 28–38 / 1.15                                                          |
| Заголовок секции дока              | Unbounded 400 | 17 / 1.4                                                              |
| Artwork status                     | Unbounded 400 | 168 / 1.1 на 2560×1440; отдельная настройка под вертикальный canvas   |
| Основной текст                     | Arial 400     | 16–18 / 1.5 на сайте, 14–16 / 1.5 в доке                              |
| Метаданные                         | Arial 400     | 12–14 / 1.5; 12 только для вторичного footer                          |
| Акцентные компактные метки overlay | Unbounded 600 | применять только там, где 400 теряет читаемость после масштабирования |

400 — основное фирменное начертание для заголовков и действий. 600 — отдельное подтверждаемое средство читаемости overlay, а не вес всего интерфейса. Поля, длинные русские тексты и данные — Arial. Не грузить 600 в потребителя, где он не используется; не подменять 400 облегчённым синтезом из 600.

Эталоны используют исходный Unbounded.ttf с его настоящим диапазоном 400/600 и font-synthesis:none. Это только визуальная проверка ролей; техническая миграция WOFF2, exports, preload, генератора и проверок остаётся этапом 4. TTF в эталоне крупнее будущей поставки; его размер не становится продуктовым бюджетом. OFL встраивается существующим preset.

## Интервалы, форма и состояния

Шкала интервалов: 4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48 / 64 px. Не каждый шаг обязан использоваться в каждом режиме. Радиусы: 6 px у компактного тега, 8 у поля/док-кнопки, 12–14 у медиаблока/ссылки, 18 mobile и 24 desktop у внешней поверхности сайта. Для artwork радиус масштабируется относительно canvas, не копируется из дока.

Граница — 1 px в браузерном UI, 2 px в canvas 2560×1440. Тени и blur не нужны для обозначения иерархии. Фокус — 3 px с отступом 4 px, без обрезки контейнером. Действия/поля не ниже 44 px; между соседними действиями есть интервал. Элемент не двигается на hover/focus. Изменение текста состояния не должно двигать другие основные элементы.

Loading сохраняет подпись и ширину действия, повторная запись заблокирована; empty объясняет следующий шаг; error сохраняет введённые данные и показывает повтор; disabled обозначен семантически и визуально. В макете дока показано несохранённое изменение; остальные состояния станут stories на этапе 5. Клавиатурная семантика и фокус из реестра обязательны независимо от внешнего вида.

Движение: [общая система](../motion.md) задаёт короткую смену цвета за 160 ms, нажатие на 1 px за 80 ms и локальное появление панелей за 160–280 ms. Главная имеет одно короткое вступление трёх групп. Нет движения на hover/focus, скачущих стрелок или мигающего статуса. reduced-motion отключает необязательные анимации. Функциональные тайминги Tuna и провайдеров сохраняются из контрактов; не заменяются общей декоративной длительностью.

## Четыре режима

| Режим                 | Композиция и плотность                                                                        | Обоснованное отличие                                                                                                    |
| --------------------- | --------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Публичный сайт        | max-width 1040, padding 48 desktop / 24 mobile, интервалы 28–36 между задачами                | крупное имя и главная ссылка помогают выбрать площадку; body больше дока                                                |
| Компактный док        | один столбец до 540, padding 16–24, поля 44+, главное действие 60, разделители между задачами | синяя рамка 10–16 px, светлая поверхность, заголовок 28–38 px и крупное главное действие сохраняют фирменную композицию |
| OBS overlay           | прозрачный внешний canvas, светлые локальные поверхности, читаемые метки                      | камера/игра видимы, контраст оценивается на разных подложках; прозрачность не навязывается статистическому доку         |
| Фиксированный artwork | размеры/safe zones по layout.json, крупный 400, утверждённые avatar/QR                        | растровая композиция не ведёт себя как responsive сайт и не содержит лишней управляющей UI                              |

Эталон сцены начала сохраняет прямоугольник чата [1740,330,640,640] и QR [2180,1160,250,250]. Смысловые блоки не занимают зарезервированные зоны alerts/donors/music. Это предложение композиции, перенос реальной геометрии и vertical/camera-вариантов — этап 6. Прототип не становится вторым источником layout.json.

## Файлы и просмотр

```sh
npm run build:ui-reference
```

Готовые автономные эталоны в `.build-cache/ui-reference/`: index.html, dock.html и scene.html. Открываются без сервера, шрифты/изображения/CSS/лицензия встроены. Для эталона сайта — index.html; док — dock.html (проверять ширину 320/390/540); сцена — scene.html на canvas 2560×1440. Навигация эталонов находится вне продуктовой поверхности. Статические кнопки дока отмечены aria-disabled: это макет состояний, не форма отправки метаданных.

Проверять: компоновку на 320/390/540 и desktop, отсутствие overflow, реальные веса шрифта, контраст и focus. Проверка макетов не заменяет функциональные тесты и экранные состояния после переноса. Screenshot baselines до согласования не создаются. Аватар и QR подключаются из существующих утверждённых файлов без перекодирования исходников.

## Уточнения после просмотра пользователем

19.10.2026: сцена одобрена. Для сайта убраны подпись Twitch/maseaaao и выдуманный текст чата; описание заменено на «Стример», ссылка сообщества — «Сообщество ЛОББИ». Не добавлять поясняющие/маркетинговые подписи без пользовательской задачи.

Первый вариант дока отклонён: недостаточно соответствует дизайн-системе. Исправленный док повторяет композиционные признаки основного референса: синий внешний фон, светлая поверхность с мягким радиусом, Unbounded 400 крупнее в заголовке и действиях, единая геометрия полей. Это замена прежнего решения, а не второй вариант для поддержки. Исправленный вариант подтверждён пользователем с дополнением: показывать загружаемую обложку категории. Фиксация воспроизводимых screenshot baselines — после закрепления среды этапа 4.

Обложка выбранной категории обязательна. В конечном доке использовать `TwitchState.categoryImageUrl` / `TwitchCategory.imageUrl` из прежнего API; сохранять имя категории при загрузке/ошибке картинки, показывать нейтральный placeholder. Изменение категории отменяет визуальный результат устаревшей загрузки. В эталоне — локальная fixture [Just Chatting](https://static-cdn.jtvnw.net/ttv-boxart/509658-188x250.jpg), 188×250, встроенная сборщиком; функциональные состояния проверять на fixtures компонентов, не обращаться к рабочему Streamer.bot ради картинки.
