# Независимые выпуски

Stream Info, Tuna, OBS Widgets, Artwork, System Microphone, VoiceStream, Windows-интеграции и сайт выпускаются независимо. Префиксы тегов: `stream-info-v`, `tuna-widget-v`, `obs-widgets-v`, `artwork-v`, `system-microphone-v`, `voice-stream-v`, `windows-integrations-v`, `website-v`; далее строгая версия `X.Y.Z`. Изменять версию продукта и CHANGELOG. Модули Companion требуют согласованной версии package.json/manifest.json. У сайта и Windows-интеграций версия хранится отдельно в `release-version.json` / `version.json`; корень монорепозитория общей версии не имеет. Lockfile обновлять только когда это требуется изменениями зависимостей/workspaces.

Выпускаемые продукты объявлены в `tooling/release-products.json`: для каждого — префикс тега, каталог, состав артефактов, команды проверки и сборки, а также признак, нужен ли браузер. Workflow не знает о конкретных продуктах: тег разбирает `tooling/release-product.mjs`, а состав архива — `tooling/package-release.py`. Добавление нового продукта — это запись в манифесте, шаблон тега в workflow и контрактный тест `tests/release-products.test.mjs`, который требует их согласованности.

После проверки исходников выполнить `python tooling/package-release.py --validate <тег>`, `node tooling/release-product.mjs <тег>`, затем `python tooling/package-release.py <тег>`. Результаты находятся в `build/release/<тег>`: полный ZIP продукта, `<тег>.manifest.json`, `SHA256SUMS`, `windows-updater.zip` и notes.md. У Stream Info и Tuna также сохраняются отдельные HTML для ручного скачивания с прежними именами. Stream Info включает импорт C#. Artwork запускает рендер окончательных изображений, а не только промежуточных HTML. Независимые каталоги результатов позволяют упаковать несколько продуктов без удаления соседних пакетов.

Манифест пакета содержит schemaVersion/runtimeLayout, продукт, версию, тег, commit, точные пути/размеры/SHA256 файлов и архива, указания по подключению и `requires`: минимальные стабильные версии других устанавливаемых продуктов. Пустой `requires` означает отсутствие объявленных зависимостей между пакетами, а не подтверждение их совместной приёмки. Локальные сборки с незакоммиченными правками годятся для проверки упаковки; официальный релиз собирается workflow из тега. Bootstrap обновлятора содержит код и каталог продуктов из того же коммита.

После явного решения о выпуске отправить тег. Workflow сверяет версию, выполняет тесты и сборку, создаёт черновик релиза, скачивает его в `build/downloaded/<тег>` и проверяет совпадение всех ассетов. Для продуктов, требующих браузер, устанавливается Chromium с системными зависимостями; Artwork также устанавливает закреплённые Python-зависимости рендера. Существующие выпуски не перезаписываются. Это ограничение workflow, а не обещание включённой в GitHub настройки immutable releases.

Публиковать черновик после проверки скачанного HTML в OBS. Общий releases/latest объединяет разные продукты; давать ссылки на конкретные теги. Исторический change-info-streamer-bot хранит прежнюю историю и выпуски; разработка ведётся здесь.

Для остальных продуктов проверять соответствующие изображения/архивы и результат штатного подключения. Старые HTML-релизы без нового манифеста остаются доступны вручную; обновлятор требует новый выпуск, старые ассеты не дописываются. В Windows доступны установка одного продукта, **всех последних стабильных продуктов** и закреплённого комплекта версий: [инструкция обновлятора](windows-releases.md). Публикация продукта не запускает обновление пользовательского стрима.

Проверки инфраструктуры: `pnpm run test:releases`. Они проверяют каталог, упаковку бинарных файлов, план без записи, все последние версии, контрольные суммы, зависимости, сохранность текущей установки при сбое второго пакета, откат, восстановление после прерывания и блокировку параллельного запуска. Выполняются в Linux CI без запуска приложений стрима.
