# maseaaao.tv

Сайт, оформление OBS и инструменты стрима. Windows-комплект доступен целиком
и отдельными ZIP продуктов для ручной установки; OBS, Streamer.bot и Companion
устанавливаются отдельно.

## С чего начать

- [Подключение из исходников](docs/local-installation.md).

## Разработка

Linux/WSL2, Bun из `.bun-version`; отдельный Node.js не нужен.
Для полной проверки нужны .NET SDK 8, системный `tar` и Chromium.
В WSL используйте Linux-зависимости, не Windows `node_modules`.

Версии внешних зависимостей задаются в `catalog` корневого `package.json`.
В `dependencies`, `devDependencies` и `peerDependencies` используйте `catalog:`;
для внутренних пакетов — `workspace:*`. Обновляйте версию в каталоге один раз
для всех потребителей, затем обновляйте `bun.lock` командой `bun install`.

Код приложений, сборки, инструментов и тестов пишется на TypeScript.
Biome запрещает исходники `.js`, `.jsx`, `.mjs` и `.cjs`; `bun run check:types`
строго проверяет типы всех этих частей. JavaScript допускается только в результатах
сборки для браузеров, провайдеров и Companion, не как редактируемый исходник.

```bash
bun install --frozen-lockfile
bun run browser:install --with-deps
bun run full
bun run check
bun run test
```

`bun install` автоматически подключает Lefthook через корневой `postinstall`.
В CI и вне Git-клона установка хуков пропускается.
Перед коммитом запускаются Biome только для staged-файлов и `git diff --cached --check`;
перед push — полный `bun run check` и внутренние тесты `bun run test`.
Хуки ничего не исправляют и не добавляют в индекс, не собирают продукты и не
экспортируют изображения. При частичном staging Lefthook временно скрывает
незастейдженные изменения в частично добавленных файлах и восстанавливает их
после pre-commit. Pre-push проверяет рабочее дерево. CI остаётся полной проверкой.
`bun run check:hooks` проверяет конфигурацию Lefthook и входит в общий `check`,
в том числе в CI. Install-скрипт зависимости не разрешён;
Lefthook запускается через Bun без отдельного Node.js.
Для Git-клиентов с урезанным `PATH` хук добавляет `${BUN_INSTALL:-$HOME/.bun}/bin`
в окружение всех проверок.
Для ручного восстановления хуков (в том числе после `bun install --ignore-scripts`)
выполните `bun run hooks:install`.

Команды из корня:

| Команда                      | Что делает                                                                     |
| ---------------------------- | ------------------------------------------------------------------------------ |
| `bun run build`              | Собирает только сайт в `dist/website`                                          |
| `bun run build:all`          | Собирает приложения, UI Gallery, HTML artwork и диагностику; без растров и TGZ |
| `bun run build:cloudflare`   | С нуля экспортирует artwork и собирает веб-набор; только Linux/WSL2            |
| `bun run build:apps`         | Собирает приложения и диагностику без подготовки artwork                       |
| `bun run dev`                | Запускает общий dev-запускатель всех браузерных продуктов                      |
| `bun run dev:ui`             | Запускает dev-сервер витрины UI/UX                                             |
| `bun run build:ui`           | Собирает автономную витрину в `dist/ui-gallery/index.html`                     |
| `bun run render:all`         | Готовит HTML artwork, экспортирует и оптимизирует изображения                  |
| `bun run full`               | Выполняет экспорт, затем сборку приложений; каждый продукт один раз            |
| `bun run build:companion`    | Собирает модули Companion                                                      |
| `bun run package:companion`  | Упаковывает готовые модули Companion в TGZ                                     |
| `bun run prepare:cloudflare` | Добавляет только маршруты и правила публикации в готовый `dist/`, без сборки   |
| `bun run check`              | Запускает линтеры и проверки типов и исходников без сборки                     |
| `bun run test`               | Запускает только внутренние тесты Stream Info и Companion                      |
| `bun run test:csharp`        | Вручную запускает C#-тесты Stream Info; нужен .NET SDK 8                       |
| `bun run verify:companion`   | Проверяет готовые TGZ Companion без сборки и упаковки                          |

`bun run dev` запускает общий dev-запускатель: оно открывает страницу с меню
(Website, Stream Info, Tuna, OBS Widgets, UI Gallery, Artwork), выбранный проект
показывается в области предпросмотра и открывается отдельной ссылкой. Изменения
исходников видны после сохранения: CSS и TypeScript обновляются горячо, HTML —
перезагрузкой страницы. Artwork показывает HTML/CSS-композиции напрямую, без
экспорта изображений; готовые изображения отдельно доступны в UI Gallery.
Виджеты предпросматриваются с тестовыми данными и реальных сервисов не касаются;
C# Actions и Companion запускателем не запускаются.

Внешних тестов репозитория и тестовой обвязки для сборок, релизов и вёрстки нет.
Тесты внутри продуктов, пакетов и `artwork` сохраняются; `bun run test` запускает
существующие внутренние тесты Stream Info и Companion.
C#-тесты Stream Info сохранены, но запускаются только вручную через
`bun run test:csharp`: общий `test` и CI их не вызывают.
`check` не требует готовых результатов и не запускает сборку или экспорт.
В CI сборка и упаковка выполняются отдельными шагами перед проверками
и внутренними тестами продуктов.
Сборки, полный экспорт artwork, проверки кода и отдельные тесты используют локальный
кеш Turborepo в `.turbo/cache`. При совпадении входов команда восстанавливает свои
результаты из кеша; исходники, конфигурация, зависимости и версии Bun, Chromium,
.NET и системного `tar` участвуют в ключе. Кеши разных ОС и архитектур разделены.
Версия пакета artwork не влияет на рендер: изменение только номера релиза
не требует повторного экспорта изображений. Сборки приложений учитывают версии
своих продуктов, сайт — также готовые изображения из `dist/artwork/brand/website`.

Для принудительного выполнения используйте `TURBO_FORCE=true bun run <команда>`.
Удаление `.turbo/cache` очищает локальный кеш. Корневые команды запускают задачи
workspace-пакетов через Turbo; общие операции находятся в `tooling/package.json`.
Для прямого запуска без кеша используйте скрипт нужного workspace. Проверки исходников
репозитория и готовых TGZ Companion, экспорт отдельных групп и команды
установки, синхронизации и публикации всегда выполняются непосредственно.
Проверки и тесты не восстанавливают и не собирают продукты вместо команды сборки.
В CI сохраняются кеши скачанных Bun/NuGet-пакетов и результатов задач;
еженедельная проверка принудительно выполняет задачи. Общего удалённого кеша
между локальной машиной и CI нет.

Для своего Chromium задайте `CHROME_BIN`. `browser:install` скачивает полный Chromium
без неиспользуемого Headless Shell. Verify и Release работают на `ubuntu-24.04`
и устанавливают Chromium с системными зависимостями. CI-среда закреплена в
[verify.yml](.github/workflows/verify.yml) и [release.yml](.github/workflows/release.yml).
Сначала меняйте исходники, затем экспорты.
После публикации GitHub Release сайт автоматически деплоится через
**Deploy website** с ID соответствующего успешного запуска **Release**.
Ручной запуск **Deploy website** также доступен. Он скачивает сохранённый `cloudflare-dist` и публикует готовые
файлы без повторной сборки: лендинг в `/`, витрина в `/ui/`, сцены в `/scenes/`,
док и виджеты в своих подпапках. Artifact хранится 30 дней; старые запуски
без этого artifact использовать нельзя. `bun run deploy:website` тоже только
загружает уже подготовленный `dist/`; Wrangler ничего не собирает.
Маршруты — `_redirects`, список публикуемых каталогов — `.assetsignore`;
служебные результаты из `dist/` не загружаются. [Подробности](apps/website/README.md).
Push в `main` после успешных проверок обновляет один черновик общего релиза `vN`.
`[skip release]` в заголовке последнего коммита пропускает обновление черновика,
но не CI. Публикация и создание тега — вручную через **Publish release**;
затем сайт автоматически деплоится из той же сборки. [Подробности](docs/windows-releases.md#выпуск-для-разработчика).

Все результаты сборки находятся в корневом `dist/`: `website/`, `stream-info/`,
`tuna-widget/`, `obs-widgets/`, `artwork/`, `companion/`, `diagnostics/`,
`windows-integrations/`, `ui-gallery/` и `release/`.
Промежуточные файлы сборок — в `dist/.cache/`; каждая команда очищает только свой
каталог, не результаты соседних продуктов. В `dist/artwork/html/` — автономные HTML,
в `dist/artwork/<группа>/` — изображения. Весь `dist/` исключён из Git.
Каждый готовый продукт содержит собственные ресурсы и переносится отдельно:
ссылок на исходники, `node_modules` репозитория или соседние продукты в нём нет.
Общие пакеты переиспользуются в исходниках, необходимые файлы включаются в сборки.
После чистого checkout сначала выполните `bun run full`: готовых изображений
больше нет в Git. Затем приложения можно пересобирать без повторного экспорта.
Требуемые среды и сервисы (OBS, Streamer.bot, Companion, Tuna) остаются внешними;
независимость каталога не заменяет их установку и настройку подключения.
