# DroidCam: одна кнопка на все сцены

`DroidCamToggle.cs` устанавливается вместе с `CameraPresentation.cs` и `obs-health/CompanionEndpoint.cs` в один
Execute C# Code. Companion вызывает его через HTTP-соединение Streamer.bot:
`POST /DoAction`, имя `OBS | DroidCam | Toggle` (кнопка `1/2/2` на странице «ГЛАВНАЯ»).

Нажатие выключает камеру: Move Source схлопывает её по высоте за 350 мс,
донатеры стыкуются с соцполосой, музыкальная панель сдвигается следом.
Верхние, средние и нижние игровые композиции сохраняют свой край или центр.
После анимации вход DroidCam деактивируется (`activated=false`), затем
скрываются все его элементы сцен и все элементы клона `КАМЕРА [clone]` — на основном
канвасе и на Aitum Vertical. Повторное нажатие включает: сначала элементы показываются,
потом вход активируется (скрытый вход не запускает видео даже после активации).

Источники определяются по UUID в исходнике; при переносе в другую коллекцию их
необходимо проверить. Каждая запись OBS проверяется чтением, поэтому молча не
применённая запись возвращает ошибку. Сцены перечисляются через `GetCanvasList` и
`GetSceneList` с UUID канваса; на сборках без поддержки канвасов используется обычный
`GetSceneList` (вертикальный канвас тогда не затрагивается).

В Companion нужны постоянные custom variables `droidcam_state` и `droidcam_label`.
Подпись кнопки — `$(custom:droidcam_label)`, цвет — выражение по `droidcam_state`
(`1` — включена). `Init` только читает OBS и синхронизирует подпись; ручные изменения
в свойствах источника между нажатиями автоматически не отслеживаются.

`TestDroidCamToggle.cs` проверяет выключение и включение (включая порядок операций),
read-only `Init`, молча не применённые записи, ошибку OBS, запасной путь без
`GetCanvasList` и камеру внутри группы — на подставных OBS/HTTP-обработчиках.

## Заглушка и арт категории

`cam-pug.jpg` — исходная заглушка 2560×1440. Скопируйте её в
`Streamer.bot/custom/assets/camera/cam-pug.jpg`. В камерных сценах она появляется
под камерой при её выключении. В вертикальном gameplay источник
`КАТЕГОРИЯ — АРТ 16:9` постоянно расположен под камерой и занимает её прямоугольник.

Отдельное действие `CategoryArtwork.cs` вместе с `CameraPresentation.cs` получает
текущую категорию Twitch, её `igdb_id` и горизонтальный artwork из IGDB. Выбирается
арт с исходным разрешением минимум 1280×720; локальный результат обрезается по
центру до 16:9 без растяжения и сохраняется максимум в 2560×1440. По умолчанию
поверх размытого арта по центру ставится обложка игры (`cover` из IGDB) с логотипом
и названием — новичку понятно, что за игра. Переменная окружения
`CAMERA_ARTWORK_STYLE=art` возвращает прежний постер без обложки. Если подходящего
арта нет, показывается заглушка; если нет обложки — остаётся арт. Готовый постер
хранится на диске как `category-<id категории>-<стиль>.jpg` и переиспользуется после
перезапуска: заново он скачивается, только когда файлу больше недели или сменилась
категория/стиль. Если обновление не удалось, остаётся прошлый постер и повтор
происходит через 30 минут; при смене категории без доступного арта показывается
заглушка.

Нужны пользовательские переменные окружения `IGDB_CLIENT_ID` и
`IGDB_CLIENT_SECRET` собственного конфиденциального приложения Twitch.
Секрет и токены не входят в импорт, изображения или Git. Токен приложения
получается и обновляется самим действием. Для переносимой локальной установки
также поддерживается приватный `custom/assets/camera/igdb.json` с полями
`clientId` и `clientSecret`; переменные окружения имеют приоритет.

`bun tooling/local/build-camera-import.ts` создаёт штатный
`dist/windows-integrations/actions/droidcam/streamerbot-import.sb`. Он также входит
в `build:windows`. Импорт заменяет переключатель с сохранением Action ID и добавляет
обновление арта при запуске Streamer.bot, смене категории/названия Twitch и каждые
30 секунд. После импорта включите `Services → Timers → Category artwork refresh`:
Streamer.bot отключает импортированные таймеры по умолчанию. Изображение копируется
отдельно до импорта. Сначала сохраните резервную копию конфигурации и убедитесь, что
запущен ровно один Streamer.bot: второй экземпляр держит старую конфигурацию,
перехватывает кнопку Companion и перезаписывает `data/actions.json` при выходе.
Первое обновление арта создаёт источники заглушки и фильтры Move через OBS API;
сам импорт не переключает камеру или сцену. Требуется установленный Move Source.
Полное положение хранится в парах фильтров ON/OFF, поэтому повторные нажатия и
перезапуск OBS не накапливают смещение.

Проверка без настоящих OBS, Twitch и IGDB (Windows, .NET SDK 8):

```powershell
$env:STREAMERBOT_ROOT = '<папка Streamer.bot>'
dotnet run --project integrations/streamerbot/droidcam/DroidCamTests.csproj -p:NugetAudit=false
dotnet run --project integrations/streamerbot/droidcam/ArtworkTests.csproj -p:NugetAudit=false
```

Тесты включают схлопывание верхней/средней/нижней композиции, восстановление после
повторной подготовки, размеры арта, кеш, смену категории, ошибки сети и заглушку.
