## Настройка после переноса исходников

Публичный исходник больше не содержит OAuth client secret. Перед установкой новой версии задать приватную постоянную глобальную переменную Streamer.bot `daClientSecret`. `daClientId` необязательна: по умолчанию сохраняется прежний публичный client ID. Значение секрета не включать в Git, экспорт для публикации или отчёт. Получать его из приватной конфигурации приложения DonationAlerts. Без секрета новая интеграция явно прекращает инициализацию. Текущая установленная копия при переносе не менялась.

# DonationAlerts → чат Streamer.bot

Настроено 08.10.2026 для Streamer.bot 1.0.7.

Донаты публикуются в Twitch и, при наличии отслеживаемой трансляции со статусом `live` и доступным чатом, в YouTube. Сообщения видны зрителям и в существующем доке чата Streamer.bot в OBS. Дополнительный док не требуется.

## Рабочая цепочка

`Streamer.bot Started` → `-- DonationAlerts Background Watcher` → C#-модуль `DonationAlerts Integration` → соединение DonationAlerts → `DonationHandler_After` → сообщения в чаты Twitch/YouTube.

- `-- DonationAlerts Code`: код подключения к DonationAlerts; предварительно компилируется при запуске.
- `-- DonationAlerts Authorization`: открывает браузер для подключения аккаунта, сохраняет полученные ключи в штатных глобальных переменных Streamer.bot и запускает фоновый обработчик.
- `-- DonationAlerts Background Watcher`: запускается автоматически; до первой авторизации пропускает подключение. Работает в отдельной блокирующей очереди, чтобы не задерживать остальные действия и не запускать несколько слушателей одновременно.
- `DonationHandler_After`: формирует сообщение `💰 Имя — сумма валюта: текст`. Голосовой донат обозначается как `[голосовое сообщение]`. Длинный текст сокращается под ограничения платформ.

Используется аккаунт бота с запасным вариантом отправки от аккаунта стримера. YouTube выбирается из последней отслеживаемой трансляции. При отсутствии активной трансляции отправка в YouTube пропускается.

## Повторное подключение

В списке Actions запустить `-- DonationAlerts Authorization` через штатную команду Run Action и разрешить доступ в открывшемся браузере. На подтверждение даётся пять минут. Команды `!da_connect` и `!da_start` не добавлялись.

Если нужно повторно запустить слушатель после ошибки, перезапустить Streamer.bot. Если в логе указано, что авторизация истекла, повторить подключение аккаунта.

## Исходники и установленная версия

Исходники расположены в этой папке. Рабочая копия C# встроена в Execute Code соответствующих действий в `../../data/actions.json`; изменение файла `.cs` само по себе не обновляет Action. Перед изменением настроек закрыть Streamer.bot полностью и сделать резервную копию либо использовать штатный импорт.

Основа подключения: [play-code-live/streamer.bot-donationAlerts](https://github.com/play-code-live/streamer.bot-donationAlerts), лицензия MIT. Для этой установки отключена проверка обновлений в чат, служебные сообщения перенесены в лог, исправлен порядок открытия браузера и очищается текст предыдущего доната. Не устанавливать другой импорт этой интеграции поверх без проверки конфликтов.

## Проверка

В текущей настройке проверены:

- Сохранение всех 43 прежних Actions и добавление четырёх новых; ссылки и JSON корректны.
- Компиляция четырёх модулей с интерфейсом установленного Streamer.bot.
- Семь проверок обработчика с подставными сервисами: маршрутизация, неактивный YouTube, голосовой донат, переносы строк, ограничения длины, отказ Twitch и отсутствие данных.
- HTTP API запущенного Streamer.bot видит новые действия.
- Авторизация выполнена пользователем; в логе есть `DonationAlerts connected.`
- Выполнение обработчика внутри Streamer.bot без данных доната подтвердило компиляцию и пропуск отправки.

Полный путь от настоящего доната до сообщения в чате ещё нужно подтвердить на следующем донате. При активном YouTube нужно убедиться, что трансляция отслеживается в Streamer.bot и сообщение появилось также там.

Резервная копия до установки: `../../backup/donationalerts-before-20261008-231935/actions.json`. Для отката закрыть Streamer.bot и восстановить эту копию. Другие рабочие настройки не менялись.

## Обновление надёжности от 09.10.2026

Текущие исходники используют общий `WebSocketMessages.cs`: полные UTF-8-сообщения до 1 МБ, ограниченное ожидание продолжения фрагмента, отмену при закрытии. Переподключение выполняется циклом с задержкой до 30 секунд; повторный запуск слушателя игнорируется, донаты дедуплицируются по ID в ограниченном наборе из 1024 записей. Состояние дедупликации сохраняется между переподключениями, но не между перезапусками Streamer.bot.

`DonationAlertsWatcher.cs` передаёт первичное получение профиля циклу восстановления: временная недоступность сети при старте не завершает слушатель до входа в цикл. При отказе авторизации требуется штатное повторное подключение аккаунта.

Проверки: `custom/maintenance/test-audit-code.ps1`. Установка в Execute Code: `custom/maintenance/deploy-audit-actions.ps1` при закрытом приложении. Статус фактического внедрения: `custom/maintenance/audit-fixes-20261009.md`. Наличие обновлённого исходника само по себе не подтверждает загрузку приложением.
