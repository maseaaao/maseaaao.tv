# Проверка и безопасное обновление Companion

Эта процедура не устанавливает модули автоматически. Исходники здесь не являются живой конфигурацией Companion.

## Проверки без действий приложений

Сборка и проверки: Linux/WSL2, Node.js из `.node-version`, pnpm из `packageManager`, .NET SDK 8 и Python 3. Готовые модули и аудиопомощники предназначены для Companion в Windows. Из корня репозитория:

```bash
pnpm run test:companion
pnpm --filter ./integrations/companion/system-microphone run build
pnpm --filter ./integrations/companion/voice-control run build
pnpm --filter ./integrations/companion/system-microphone run package
pnpm --filter ./integrations/companion/voice-control run package
python integrations/companion/shared/test-packages.py
```

Зависимости NAudio/Newtonsoft.Json и reference assemblies .NET Framework 4.8.1 восстанавливаются через NuGet; версии и хеши закреплены в `packages.lock.json`, CI использует locked mode. Windows SDK, PowerShell и установленный Streamer.bot для сборки не нужны. Сборка компилирует помощники, но не запускает их. Тесты используют подставные обработчики и собственный локальный тестовый сервер; Actions, звук и эфир не затрагиваются. Упаковка создаёт tgz и локальные JSON-запросы; создание этих файлов не означает установку, отправлять JSON автоматически нельзя.

Артефакты:
- `system-microphone/local-system-microphone-1.3.1.tgz`
- `voice-control/local-voice-stream-1.1.1.tgz`

## Обязательный барьер перед установкой

1. Получить текущие настройки через штатный экспорт Companion (не подменять их старой копией/БД на диске). Сохранить экспорт приватно и убедиться в возможности штатного восстановления. Сохранить предыдущие пакеты модулей для отката.
2. Проверить **до установки**: у каждого `local-system-microphone` явно задан `dataFlow=capture` или `render`; endpoint ID не менять. Для `local-voice-stream` указаны два различных корректных UUID Actions запуска/остановки; чтением списка Actions подтвердить, что оба существуют, включены и имеют нужное назначение. Имена больше не используются как fallback.
3. Если проверка не пройдена, остановить обновление. Недостающие настройки вносить отдельно через интерфейс владельца и только с разрешения; не редактировать рабочую БД, JSON на диске, Junction или конфигурацию работающего приложения.
4. В согласованное окно без эфира импортировать оба tgz через менеджер модулей Companion и выбрать новые версии **в существующих соединениях**, сохранив ID соединений, кнопки, назначения действий, feedback и все настройки, включая секреты. Не пересоздавать соединения. Импорт пакета сам по себе не доказывает смену версии соединения.
5. Сверить чтением фактические `moduleVersionId`, обязательные настройки и состояние соединений. Не нажимать кнопки звука/эфира ради проверки. Проверить журнал на ошибки старта и исправность штатного экспорта после обновления. Реальное действие — отдельный согласованный тест.
6. При проблеме вернуть предыдущие версии в тех же соединениях. При необходимости восстановить совместимый штатный экспорт средствами Companion. Не копировать БД поверх работающего приложения.

Не запускать `main.js` или EXE помощников напрямую для проверки: это может подключить живые сервисы или аудиоустройства. Компиляция и статическая проверка не доказывают работу в загруженном Companion.
