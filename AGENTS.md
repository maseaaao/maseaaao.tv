# Работа с maseaaao.tv

Общаться по-русски. Начать с [README](README.md) и README затронутого продукта.
Предпочитать небольшие изменения и существующие инструменты; не добавлять
миграционные планы, описи и журналы приёмки вместо работающего результата.
- Сначала искать простое и лёгкое готовое решение в официальной документации
  и уже установленных пакетах. Свой код писать только при конкретном ограничении
  готовых решений; он тоже должен оставаться простым. Если это не получается —
  предложить простую альтернативу и объяснить компромиссы.
- Локальная разработка и визуальная проверка возможны в Windows; CI работает в Linux.
  Версию Bun брать из `.bun-version` в корне; отдельный Node.js не нужен.
  Установка: `bun install --frozen-lockfile`; один `bun.lock`, isolated linker.
  Не разрешать install-скрипты всем зависимостям. Сохранять NuGet lockfiles.
- Основные команды: `bun run build`, `bun run check`, `bun run test`.
  Запускать нужные тесты и сборки, затем `git diff --check`; сообщать реальные
  результаты и ограничения. Тесты сохранять только внутри продуктов, пакетов
  и `artwork`; внешние тесты и их обвязку не добавлять. Линтеры и проверки типов
  сохранять. Проверки не должны запускать сборку или экспорт продуктов.
- Редактировать исходник перед экспортом; не форматировать generated files
  как source. Не скрывать расхождения результатов ослаблением проверок.
  Растры принимать после просмотра изменений с учётом возможных различий рендера сред.
- `packages/design` — палитра/шрифты, `packages/ui` — общие компоненты,
  `packages/build-config` — только сборочная конфигурация. Использовать workspace
  exports, не копировать зависимости между пакетами. Правила: [дизайн](docs/design.md).
- Сохранять API, Action ID, настройки, URL-параметры, тайминги, ретраи и lifecycle
  провайдеров. Кеш Stream Info — 5 секунд со сбросом после записи.
- Не запускать apply/install/configure, Actions, эфир, музыку или отправку
  сообщений ради проверки. Тестировать на подставных обработчиках.
  Не редактировать живые базы при работающем владельце. Установка и импорт C#
  или Companion — отдельные разрешённые операции с резервной копией.
- Не коммитить секреты, базы, аккаунты, логи, зависимости и диагностику.
  Сохранять лицензии, утверждённые аватар/QR и Windows runtime/запускатели.
- Один релиз `vN`: общий ZIP и отдельные ZIP продуктов для ручной установки; обновлятора нет.
  `N` — run number workflow Release; общая внутренняя версия продуктов — `2.0.N`.
  Push в main после проверок обновляет один черновик; тег и публикация — вручную.
  `[skip release]` в заголовке head-коммита пропускает черновик, но не CI.
  Без поручения пользователя не публиковать сайт/релиз и не менять live config.
